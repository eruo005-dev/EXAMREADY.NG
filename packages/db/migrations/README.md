# Migrations

Three sources, applied in this order by `src/migrate.ts`:

1. **`local/`** — local-dev-only stubs. Creates the `auth.users` table that Supabase normally provides. Runs only when `LOCAL_DEV=true`.
2. **`*.sql`** (root of this directory) — generated by `pnpm db:generate` from the Drizzle schema. Tracked in Drizzle's `_journal.json`. Do not hand-edit.
3. **`extras/`** — hand-written SQL for things Drizzle can't express:
   - `0001_auth_link.sql` — FK + trigger linking `public.users` to `auth.users`
   - `0002_updated_at_trigger.sql` — auto-bump `updated_at` columns
   - `0003_rls_baseline.sql` — enable RLS, install public-read policies for catalog tables

Extras are tracked in a `public._extras_applied` table for idempotency.

## Adding a schema change

```bash
# 1. Edit packages/db/src/schema/*.ts
# 2. Generate the migration
pnpm db:generate
# 3. Review the SQL in migrations/<timestamp>_*.sql
# 4. Apply
pnpm db:migrate
```

## Adding hand-written SQL

Drop a new file in `extras/` with a higher number than the previous (e.g. `0004_my_change.sql`). It will be applied once and recorded in `_extras_applied`.

## Production vs local

- **Local:** `docker-compose` runs vanilla Postgres → `LOCAL_DEV=true` → stubs + generated + extras
- **Production:** Supabase project → no local stub → generated + extras only
